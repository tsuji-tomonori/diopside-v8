# コンテンツ整備状況と有限計画

`npm run audit:content-coverage -- --limit 10` は公開対象の正本を読み、機能別の状態と新着順の有限計画を表示する。ネットワーク取得、PR作成、台帳更新、生成、公開は行わない。

- `--order oldest` で過去動画を先にする
- `--features timestamps,synopsis` で対象機能を絞る
- `--claims .devflow/run/claims.json` で確認済みの既存PR snapshotを反映する
- `--output .devflow/run/coverage.json` で動画別の状態も一時保存する
- `--limit` は1〜1000。1動画を1対象とし、複数の不足機能をまとめる

claimsの形式は `enrichmentClaimsSchema` を正本とする。`schemaVersion: "1.0.0"`、確認日時 `checkedAt`、配列 `claims` が必要で、各項目は `videoId`、`features`、`pullRequest` を持つ。任意の `state` は `in-progress`、`blocked`、`awaiting-review`。PRの更新日時を確認できた場合だけ `updatedAt` を入れる。実在の開いているPRを最新状態で確認し、機能が確定できないものは推測で追加しない。

## 状態の解釈

`present` は正本にその機能があるという意味で、タグの網羅性、文章の正確性、全編の文字起こし品質の保証ではない。タイムスタンプの `短尺` と `対象外` は現行正本の理由を保って `not-applicable` とし、自動再生成しない。利用者の対象拡張指示があるときは、その理由自体を別途再評価する。

絵文字総数と推移は別機能である。取得・集計した結果のゼロ件は `present`、集計そのものがない場合は `missing`。ワードクラウドには根拠素材の種類を示し、字幕由来を視聴者チャット由来と呼ばない。文字起こしとハイブリッド索引の状態は公開正本から確認できないため `unmeasured` とする。

母数は登録済み・現行除外適用後の動画であり、すべてのYouTube動画を発見した証拠ではない。外部出演の候補発見、既存除外の再評価、公開済みbundleとの差分確認は別途必要である。

## 再開と重複防止

同じ正本・条件・claimsから同じ対象と指紋を得る。`heldWork` は未完成のまま既存PRへ保留する機能で、完成件数へ加えない。同じ動画の別機能も正本ファイルを共有するため、新しいPRを重複計画しない。`claimFeatures` は既存PRが明示的に確保している機能であり、保留した全機能をそのPRが実装するとの推測はしない。古いPRや停止中PRも自動奪取しない。担当PRを確認してから再開方針を決める。

このsnapshotは排他lockではない。計画の `executionReady` は常にfalseで、実行前に最新mainの正本指紋、除外、既存PRを再確認する。既存のタイムスタンプ／あらすじハーネスを使い、原子的claimが成功した機能だけを処理する。未知状態や資料不足に成功値を補わない。生字幕、チャット本文、投稿者識別子、秘密情報をsnapshotや公開成果物へ含めない。

# 外部受入確認

`operations/acceptance-evidence.json` のうち、自動試験で代替できない証拠だけをこの手順で確認する。請求画面、利用者の氏名、画面録画などの生資料はGitへ保存しない。

## 月次請求0円

1. 対象月のGitHub請求・利用量画面と、このサービスに利用する外部サービスの請求画面を所有者が確認する。
2. 既存のChatGPT／Codex契約、既存端末、電気、通信回線を除外し、GitHub、配信、データ取得、保存、検索、監視、ドメイン、外部APIの請求合計が0円であることを確認する。
3. 0円を確認できないサービスがあれば公開更新を停止する。
4. 個人情報や請求明細を含めず、対象月、合計0円、確認日時をIssueまたはプルリクエストへ所有者の確認記録として残す。
5. `monthlyCost` の `status`、`month`、`totalServiceChargeJpy`、`verifiedAt`、確認記録の `evidenceUrl`、`finding` を更新する。

## 初見利用者のモバイル試験

公開URLを使い、diopside v8を操作したことがない利用者へ、375×812画素の画面で次の5課題を順不同で依頼する。操作方法は説明せず、課題の読み上げ終了からYouTubeが開くまでを計測する。

| 課題ID | 課題 |
| --- | --- |
| `title-fragment` | タイトルの断片から目的の動画を検索し、YouTubeで開く |
| `title-typo` | 1文字の入力誤りを含むタイトルの記憶から目的の動画を検索し、YouTubeで開く |
| `tag-filter` | 指定されたタグを使って動画を絞り込み、YouTubeで開く |
| `date-duration` | 指定された公開日と動画長を同時に使って動画を絞り込み、YouTubeで開く |
| `combined-filter` | タイトル、タグ、公開日、動画長を組み合わせて目的の動画を探し、YouTubeで開く |

完了したかと秒数だけを記録する。氏名、録画、自由記述の生データは保存しない。5課題中4課題以上が60秒以内なら、`mobileUsability` の `status` を `合格`、`taskCount` を5、`passedWithin60Seconds` を実測値にし、5件の `results` と確認所見を記録する。条件を満たさない場合は `不合格` とし、画面改善後に別の初見利用者で再実施する。

## 監査

更新後に `npm run audit:requirements` を実行する。外部証拠が不足する要件は未完了のままにし、自動E2Eや推測値で合格へ変更しない。

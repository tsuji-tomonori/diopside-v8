# 配信アーカイブの公開照合

配信元で候補を発見しただけでも、GitHubにDraftを作っただけでも、公開は完了しません。日次確認・中断再開時は、新規IDだけでなく、直近の対象期間と前回から残っている未完了IDを照合します。同じIDに作業中のPRがあれば、別のPRを作らず、続きから進めます。

## 入力

最新の `main` を取得した作業ツリーで実行します。既存の配信探索・台帳・GitHubコネクターから、対象範囲の確認済みデータを次の形へ縮約し、`.devflow/run/` に置きます。非公開・会員限定の配信は対象にしません。他チャンネル分は白雪巴さんの出演根拠を確認したものに限ります。

```json
{
  "discovered": ["IH7YlUrpUIs"],
  "timestampsLedger": [{ "videoId": "IH7YlUrpUIs", "complete": false }],
  "synopsisLedger": [{ "videoId": "IH7YlUrpUIs", "complete": false }],
  "pullRequests": []
}
```

- `discovered` は今回照合する公開動画ID。上記の期間と未完了分を動画IDで重複排除し、未確認の配信元や期間は報告に明記します。
- 両台帳の `complete` は「作成済み」欄の真偽です。行がなければ配列に入れません。取得に失敗した台帳を空配列で代用しません。
- `pullRequests` には対象IDにひもづくすべての開いているPRを入れます。各要素のキーは `videoId`, `number`, `headSha`, `draft`, `mergeable`（不明は `null`）, `check` です。`check` は観測した内容検証の `{ "headSha": "<40桁SHA>", "conclusion": "running|success|failureのいずれか" }` または `null`。古いSHAの成功は再利用しません。
- 生の字幕・チャット・コメントや認証情報は入力しません。出力はID・状態・PR番号・SHAのみです。

```sh
mkdir -p .devflow/run
npm run audit:archive-publication -- .devflow/run/archive-input.json .devflow/run/archive-audit.json
```

## 結果に応じた再開

| 段階 | 次に行うこと |
| --- | --- |
| `register` / `prepare` / `enrichment-missing` | 台帳に行がなければ登録。登録済みは未作成部分から着手する。 |
| `open-pull-request` | 既存PRを続ける。競合、最新CI未確認・実行中・失敗、Draftは `pullRequests` の状態で区別し、安全に解消できるものから進める。 |
| `awaiting-publication` | PRを作り直さず、main由来の生成PRとPages公開を確認する。 |
| `published` | 公開索引と公開詳細に時刻・あらすじあり。台帳の公開済み欄が実データと違えば、別途現在行を再読し、同一IDと更新条件を確認して取り直す。 |
| `excluded` / `public-not-in-canonical` | 前者は掲載対象外。後者は別版を比較した可能性があるため、最新mainと公開版を取り直す。 |

照合は読み取り専用です。実行中に公開版が切り替わったり、索引にある動画の詳細を取得できなかったりしたときは中断し、「未掲載」に数えません。成功した照合もマージ可否やコンテンツの正確性を認定するものではありません。親は最新headの実差分・検証とその依頼の承認範囲を確認し、権限があるときのみ後続の操作を行います。通知のみの依頼ではマージしません。複数の動画PRを同じmainに合わせても、共通の `content/content-manifest.json` は1本目のマージで変わります。次のPRは新しいmainに対して競合とCIを取り直します。カウントを旧ブランチから足し合わせず、最新mainとそのPRの対象動画1本から算出します。競合やCI失敗などで完了できなければ、残件ごとに理由と再開条件を残します。成功時は公開索引と詳細を再読し、台帳と照合してから完了とします。

# 配信タイムスタンプ生成方針 v1

## 対象

`tags/video_tags_v2.json` と `tags/collaboration_video_tags_v2.json` の全動画から、次の条件で抽出する。

- `公開形式 > 動画形式 = 配信`
- `内容 > 歌種別 = 歌ってみた` は除外

歌枠、歌リレー、音楽ライブは配信なので対象に含める。単曲の歌ってみた動画とShorts、収録動画は含めない。

対象集合は `scripts/build_timestamp_manifest.py` で再生成し、`timestamps/target_manifest_v1.json` を正本とする。

2026-07-12時点の抽出結果は1,800本、合計4,677.362時間である。内訳は本人チャンネル1,158本、外部チャンネル642本となる。YouTubeメタデータを取得できていない外部動画が13本ある。

## 生成するタイムスタンプの粒度

最初に生成するのは見どころ集ではなく、動画全体を移動するための章である。固定間隔では区切らず、出演者、コーナー、試合、ステージ、話題等の内容境界を使う。

- 通常の2時間配信は6〜15章を目安とする。
- 出演者やコーナーが頻繁に変わる企画は3〜10分程度でも区切る。
- 雑談、ゲーム、TRPGは10〜30分程度を基本とする。
- 一言、リアクション、短い名場面は章にせず、将来の見どころデータとして分離する。

ジャンルごとの主な境界は次の通り。

| 主ジャンル | 境界 |
|---|---|
| ゲーム | ゲーム開始、試合、ステージ、章、ボス、エンディング、感想 |
| 企画 | 説明、コーナー、出演者、休憩、結果、告知 |
| 雑談 | 大きな話題転換、投稿テーマ、告知、スパチャ読み |
| ASMR | 道具、左右、施術、シチュエーションの切替 |
| 歌 | 各曲、MC、告知 |
| 朗読・声劇 | 作品、幕、場面、出演者の切替 |
| 同時視聴 | 同期、本編、話数、休憩、終了、感想。章名はネタバレを避ける |
| TRPG | 導入、幕、場面、休憩、感想。章名は核心を伏せる |

## 処理順序

1. `yt-dlp` のチャプター、概要欄、保存コメントから既存タイムスタンプを回収する。
2. `ja-orig`、`ja` の順でYouTube字幕を再収集する。
3. 字幕が取得できない動画は全編を音声認識する。コメント候補周辺だけの部分ASRでは、コメントに記載されていない章境界を見落とすためである。字幕がある動画では、大きな字幕欠損や境界時刻の補修に限り部分ASRを使う。
4. 字幕の話題転換、進行語、無音、映像変化、コメント、ライブチャット、動画タグから境界候補を作る。
5. 境界前後の字幕と正規化済みタグを根拠に短い章名を生成する。
6. 機械検証し、低信頼またはネタバレの可能性がある結果をレビューへ送る。

既存概要欄のタイムスタンプは自動生成結果で上書きしない。視聴者コメントは有力な候補として使うが、そのまま確定結果にはしない。

初回回収では、概要欄に3点以上のタイムスタンプがある動画を18本確認した。このうち、そのままYouTubeチャプターの形式要件を満たすものは16本だった。また、視聴者コメントに3点以上の昇順タイムスタンプがある動画を1,147本確認した。コメント候補は対象全体の約64%を覆うため、境界候補として先に利用し、字幕で内容と時刻を照合する。

## YouTubeチャプターとしての検証条件

- 先頭が`0:00`
- 3章以上
- 開始時刻が昇順
- 各章が10秒以上
- 動画時間を超えない

このほか、連続する同一章名、極端な過分割、タグと異なる作品名・出演者名、TRPG・同時視聴のネタバレを検査する。

## パイロット

全件処理前に30本で生成品質を確認する。内訳はゲーム8、企画6、雑談5、ASMR3、歌2、朗読・声劇2、同時視聴2、TRPG2とする。本人・外部、字幕あり・なし、既存タイムスタンプあり・なしを混在させる。

評価項目は、境界時刻のずれ、章数、章名の正確さ、過不足、ネタバレ、1時間あたりの処理時間とする。概要欄に既存タイムスタンプがある動画は評価用の基準データとして別途すべて保持する。

選定した30本のうち25本では日本語字幕を取得できた。残る5本は年齢制限のあるゲーム・ASMR配信だが、いずれも視聴者コメントのタイムスタンプ候補がある。パイロットではこの5本を「字幕なし・コメントあり」の経路として評価する。

### 初回候補生成の結果

30本すべてでYouTubeの形式要件を満たす候補列は作成できたが、内容品質の合格は概要欄由来の5本だけだった。

- 概要欄由来5本: 作成者が付けた章なので、そのまま採用可能。
- コメント由来20本: 時刻は有用だが、章ではなく短いリアクションや名場面が多い。固定間隔で間引くだけでは、話題やストーリーの境界にならない。
- 字幕構造語由来5本: 「試合」「終了」「感想」等を会話中の一般語からも拾い、誤った章名が生じる。キーワード抽出だけでの公開は不可。

したがって、コメントは確定章ではなく境界候補として扱う。候補時刻の前後だけでなく、20〜30分の重複チャンクに分けた文字起こし全体を必ず読み、同じ話題・試合・コーナーをまとめ、章名を付け直す工程が必要である。字幕がない動画は全編ASRを行う。部分ASRは既知候補の時刻補正には使えるが、動画全体の章を発見した証拠にはしない。

最終生成器の品質ゲートでは、YouTube形式要件と内容品質を分離する。`youtubeChapterEligible=true`だけでは採用せず、境界の意味、章名、粒度、ネタバレを確認した`qualityGatePassed=true`のみを確定データへ移す。

## Skill・サブエージェント構成

現時点では字幕あり92本、コメントあり1,372本、ライブチャットあり146本で、421本は三つすべてがない。421本は音声取得と全編ASRが完了するまで章判定を開始しない。

| 工程 | Skill / Agent | Model |
|---|---|---|
| 全体調停 | `$generate-stream-timestamps` / root | `gpt-5.6-luna`, low |
| 証拠正規化 | `$prepare-stream-evidence` / `timestamp-evidence-preparer` | `gpt-5.6-luna`, low |
| 全編ASR | `$prepare-stream-evidence` / `timestamp-asr-recovery` | `gpt-4o-transcribe`。調停agentは`gpt-5.6-luna`, low |
| 全文チャンク分析 | `$compose-stream-chapters` / `timestamp-transcript-mapper` | `gpt-5.6-luna`, high |
| コメント・チャット分析 | `$compose-stream-chapters` / `timestamp-audience-mapper` | `gpt-5.6-luna`, low |
| 動画全体の章統合 | `$compose-stream-chapters` / `timestamp-chapter-composer` | `gpt-5.6-luna`, high |
| 根拠監査 | `$audit-stream-chapters` / `timestamp-fact-checker` | `gpt-5.6-luna`, high |
| 粒度・ネタバレ監査 | `$audit-stream-chapters` / `timestamp-editorial-reviewer` | `gpt-5.6-luna`, high |
| 最終整形 | `$audit-stream-chapters` / `timestamp-finalizer` | `gpt-5.6-luna`, low |

各動画は`timestamps/work/v1/{videoId}/`に独立して保存する。`manage_parallel_work.py`で異なる動画だけを排他的にclaimし、同一動画は常に一agentずつ処理する。証拠準備、全文チャンク分析、全体統合、別contextでの二つの独立監査を順に通し、二つの監査が合格した動画だけ`final.json`を作る。複数agentが一つの巨大な集約JSONを直接編集してはならない。

## 成果物

| ファイル | 用途 |
|---|---|
| `timestamps/target_manifest_v1.json` | 対象動画と入力データの取得状況 |

外部チャンネル動画は説明文を変更できないため、全件共通のJSONを先に完成させる。YouTube概要欄用テキストへの変換と本人チャンネルへの反映は、その後の独立工程とする。
